# Output Contract

All agents working in this repository should follow this output contract unless a task explicitly requires a different format.

## Required Qualities
- concrete
- implementation-oriented
- reviewable
- assumption-aware
- scoped to the task

## Minimum Required Sections
- Summary
- Assumptions
- Proposed Changes
- Acceptance Criteria
- Risks
- Next Steps

## Additional UI Requirement
For every UI-related output, include these headings exactly:
- Purpose
- Apple HIG Basis
- NeXT / OPENSTEP / GNUstep Influence
- Layout Description
- Interaction Behavior
- Visual Styling Notes
- Accessibility Notes
- Implementation Considerations
- Self-Check Result

## Additional Engineering Requirement
When the task affects implementation, also mention:
- impacted files or modules
- migration implications if any
- test implications if any

## Prohibited Output Patterns
- vague aesthetic-only commentary
- generic trend-driven advice without project fit
- ignoring privacy or public-repo constraints
- omitting assumptions on ambiguous tasks
